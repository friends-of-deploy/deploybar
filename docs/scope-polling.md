# Account scopes and polling

GitHub organization discovery uses owners returned by authenticated `GET /user/repos`. GitHub's `GET /user/orgs` returns an empty list for fine-grained personal access tokens. Discovery and organization repository filtering scan up to ten pages of 100 accessible repositories, sorted by push time. Organizations whose accessible repositories fall beyond that limit are not discovered. Organizations with no accessible repositories are absent.

Organization scopes filter that authenticated list by owner login. They do not query `/orgs/{org}/repos`, which can include public repositories unrelated to the token's selected repositories. Personal scopes retain the existing `affiliation=owner` boundary; repositories owned by another individual are not added as a new scope. Organization and personal results retain account-level deployment/project deduplication.

GitHub organization scopes share one authenticated `/user/repos` listing per poll tick, at most ten pages, fetched once for all of an account's organizations. Beyond it, an organization costs one workflow-runs request per repository, up to twenty; the estimate comes from the organization's last result and is twenty until there is one. The personal scope keeps its own owner-only listing and is budgeted at the 40-request worst case. Each tick may spend the account's share of the hourly allowance — 41 requests every 30 seconds at 5,000/hour — less the shared listing and the by-id re-reads of in-progress runs (at most ten), and packs scopes in rotation order until the next would not fit, always taking at least one. The in-progress re-reads get only what the share leaves after the tick's fetches, so a tick spent on the personal scope re-reads at most one run, and an account sitting out a slower-cadence tick re-reads none. A poll between timer ticks (a refresh click, a wake, a scope change) spends only the share earned since the account's last poll, with no at-least-one floor, and resets that clock, so the next tick gets the remainder. At a 10-second configured interval the account fetches only every third tick, since the costliest scope needs a 30-second share. Vercel retains its two-request estimate and 20,000/hour scheduling allowance.

This is conservative scheduling, not an absolute GitHub quota guarantee. Discovery costs up to ten additional requests, auth retries and manual refreshes of Vercel accounts can add traffic, and multiple accounts or other applications may share a credential's quota. GitHub's returned rate-limit response remains authoritative. Default 30-second GitHub polling plans at most 4,920 requests/hour, listing and re-reads included, however often the user refreshes; an organization that gained repositories since its last result can exceed its estimate, by at most that growth up to twenty, for one tick.

Cached rows seed both the per-scope replay store and notification baseline. A scope waiting for its rotation turn retains its cached rows. Each previously unseen scope's first successful response establishes a silent baseline, while a state change from a restored cached baseline can notify. A scope disabled or removed during an in-flight request is rejected before merge and notification diff, including results that completed before another slower scope.

Startup and newly connected accounts use the same account-specific organization discovery: GitHub token/CLI accounts discover repository owners, and Vercel token/CLI accounts discover teams. Injected legacy CLI transports remain supported. Discovered scopes join the normal budgeted rotation.
